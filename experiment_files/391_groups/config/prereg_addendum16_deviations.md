## Correction to D16-4 (2026-11-14, user request): timing of the rule
The D16-4 stop / list-cut rule was set AFTER shard-0 outputs existed, not before. Sequence: (1) v1 run of B shard 0 (job 11867053) stopped generation at the first newline; its meta file (raw/a16_B/superseded_20261114/meta/shard_000.json, written 06:10:50) contains a per-condition summary ('quick': mean true and chance match rates over the 50 shard-0 papers, e.g. F0 any author 0.14); (2) the generated texts showed that F1/F2 answers written as vertical lists ("\n1. …") were cut after the first marker; (3) the rule was changed to "generate to 80 tokens / EOS, cut the list afterwards" (v2, meta_v2 written 06:34:47) and the parser was tightened afterwards (v2b). The motivation was the truncation of list answers, not any condition contrast, but shard-0 summary rates (50 papers, no intervals, no group split) had been computed before the change and may have been seen by the implementing helper. The user's approval of D16-1 … D16-6 came later the same day. The full-sample B / D results (all other shards) did not exist at that time.

## Check of the F4 control (user request 2026-11-14): no D16-7 needed
The F4 chance baseline is already implemented: for each paper a control paper from the same field whose first author has the same first initial is fixed in advance (ctrl_f4_paper_id; found for 100% of papers), and the model's F4 completion is matched against that control paper's first author with the same rule (score_gen: c_first_sur, c_first_sur_pos1; prereg16_a16.py line 600). Giving the control paper's first initial in the prompt would produce the identical prompt (same letter by construction), so a separate prompt condition is not needed; main comparison for F4 = true first-author surname match − chance (same-initial control) match.
