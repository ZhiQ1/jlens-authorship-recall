Q1　target / control 是怎么定义的？分组本身可靠吗？

两组都是开放回答写不出作者的论文（R0/R1，即 HR2 > 0.5）：target 要求 4 个选项顺序全答对且真字母平均概率 ≥ 0.5，control 是 4 个顺序里最多答对 1 个，全队列 4,621 / 2,220 篇。标签是组长的标注包原样数据，我们按规则重算 group_tight 与标签 100% 一致。可靠性的弱点有两处：0-2 引用档的收紧通过率 25.5%，接近固定偏好某个字母的 25%；500 篇第二套干扰团队重测一致率 83.6%（kappa 0.63）。所以 Stage 10 加做了去掉低档的敏感性（final +0.212 [0.199, 0.226]）。标签由组长的 elm 代码生成（不是 Dreaming Up Authors 的 dua 包），干扰团队的抽取规则原文未知（bin_window 等字段含义已从数据推断），需向组长确认。见 g-labels-groups、s19-s1-cohort、s1011-s10-tc。

Q2　假标题怎么选？"79% 来自严格档"是什么意思？

每篇在同领域其他论文中找 5 个 donor，硬排除自身、任何共享姓氏、标题词 Jaccard > 0.6；代价 = |Δyear|/5 + |Δn_authors|/max(1, 0.25n) + |Δtitle_tokens|/max(1, 0.2·len) + 1.5·|Δbin|，按 strict → medium → loose → nearest 逐档做最小代价指派。79% 指全部 45,540 个（论文, 假标题）配对中 35,898 个来自 strict 档（0.7883），不是"79% 的论文 5 个都是 strict"（那是 6,056 / 9,108 = 66.5%）。假标题提示保留目标论文自己的年份，只换标题。代价权重是经验设定，没有做过敏感性分析（用户 2026-10-30 确认）。见 h-false-cost、h-false-79、h-false-limits。

Q3　标题特异信号能排除"名字本身好猜"吗？

spec = 真标题 − 5 个假标题平均，七个条件用同一组名字 token、只换提示，所以名字自身的难度在差值中抵消；标点 token 的 spec 最大约 0.014，作为阴性对照。Stage 12 又直接测了先验：删标题时真名单在 4 个多选选项中最"像"的比例 0.255（≈ 机会 25%）；纯名字提示下 target − control 只有 +0.047 [+0.031, +0.062]，约为真标题差 +0.247 的 19%（两个点估计之比，未对比值本身做 bootstrap）。所有结论都是 teacher forcing 下的偏好，不是生成。见 g-scoring-spec、s1011-s10-titlespec、s12-n1、s12-n2。

Q8　E2 注意力阻断具体怎么做？为什么被挡的格子是 bf16 最小值？

每个 decoder layer 用 forward pre-hook 把 attention_mask 换成形状 [B, 1, T, T] 的显式加性 mask：允许处为 0，禁止处为 torch.finfo(bf16).min（不是 −inf），第二维为 1 所以对所有头生效；禁止的是"标题之后所有 query 位置 → 全部标题 token key"，从第 l 层一直挡到 L63。显式 mask 让 sdpa 走 is_causal=False、不走 GQA 快路径，换了内核，所以基线用同批"什么都不挡但走同样 mask 路径"的 l = 64 那一份；smoke 中该基线与 Stage 10 名次相同 0.7037（阈值 0.75，记 WARN），CPU 真权重检查显式 mask 基线与不加 mask 完全相同。正文没有记录选用 finfo.min 而非 −inf 的理由，未知，需向 Stage 11 原作者确认。见 s1011-s11-e2、s1011-s11-qc。

Q9　E1 的"标题之后"包括名字位置吗？"L48 恢复 83%、L52 100%"怎么算的？

包括。替换区间 = 对齐尾段（闭引号、" ("、4 个年份数字、")?\n"、"Authors"、":"，共 8 或 9 个 token）+ 全部名字输入 token，所有打分位置都在被替换的区间内，所以"恢复"不能单独归于名字前的提示位置。恢复率 = mean_p(替换 − 假) / mean_p(真 − 假)：all 组 L48 0.825 [0.807, 0.842]，L52 0.996 [0.989, 1.003]。Stage 12 P1 逐位置拆开：L52 名字位置 0.847、":" 0.172，其余单个提示位置都很小；X6 用另外 4 个假标题重做，target L48 0.788–0.803、L52 0.984–0.990。E1 的替换运行是 batch 15、假基线是 batch 1，舍入噪声估计约 0.01、远小于主效应；用户决定答辩前不补测，GPU 空闲时按 X4 的做法补。见 s1011-s11-e1、s12-p1、s13-x6、s1011-s11-qc。

Q10　E4b probe 到底测了什么？有哪些设计上的漏洞？

输入是标题最后一个 token 的第 l 层残差，目标是同一运行中 ":" 位置的 L63 残差，闭式 ridge（α 只在第 1 折上从 {0.1, 1, 10} 选，各层都选中 1.0），预测经 final norm 与 4,314 行名字词表求名次。只打每位作者的第一个名字 token（73% 是首字母），姓的首 token 不作 gold；spec = 真标题输入 − false_0 输入。标准化的 μ、σ 用全部 9,108 篇（含测试折）算，是只影响标准化的轻微泄漏；而 Stage 10 显示首字母 token 几乎不带标题特异信号，所以 probe 测的恰是信号最弱的那部分。标准化问题已于 2026-10-30 改为只用训练折重算（作业 11500917）：最大差 0.0075，α 不变，确认版没有"区间是否含 0"的翻转，L44 下界变为 +0.000（边界）；gold 只用第一个 token 的问题没有改。见 s1011-s11-e4b、s1011-s11-e4b-check、s1011-s10-format。

Q11　E4b 的泄漏是怎么发现和处理的？结论变了吗？

2026-10-28 审读发现两类泄漏：同作者团队跨折，以及"标题一题两用"（测试论文的假标题是训练折某篇的真标题，或反过来）。复核脚本 stage13_e4b_group.py（作业 11443587）只替换分折行并注入剔除规则，paper/不剔除配置复现已发表数字（最大差 0.0000）。确认版（团队折 + 剔除）只剩 1,863 篇（target 896、control 499），target − control 变大：L24 +0.024 → +0.052 [0.017, 0.088]，L56 +0.039 → +0.075 [0.038, 0.115]，置换 gold 对照仍 ≈ 0。原"只用假标题训练的 probe 更强"（L24/40/56 = +0.068/+0.081/+0.094）来自泄漏，复核后 +0.050/+0.057/+0.074，该说法已撤回。剩下的论文不是随机子集。见 h-leak、s1011-s11-e4b-check、s12-cpu。

Q12　M2 的 false_0 泄漏影响多大？

false_0 共 6,247 个 donor，其中 2,373 个被多篇借用；按论文随机分折后 2,004 个 donor 标题同时落在训练与测试折。按 donor 及其团队分组重跑（作业 11443403）后，L48 donor 年份 R² 0.623 → 0.535、log 引用 0.588 → 0.488；真标题运行两种切法只差 ≤ 0.005。补充 1 判定按论文切的 false_0 数字无效。M2 原来的区间是按论文 bootstrap 200 次；2026-10-30 按补充 2 补算团队整群 2,000 次（作业 11503585）：176 个点估计全一致，区间平均宽 1.15 倍（true 1.02、false_0 1.32），0 个翻转。见 h-leak-a、s13-m2。

Q13　M3 的迁移比接近 1、X1 三种来源恢复一样好，能说明"论文身份"吗？

不能单独说明。三种问法只在标题前 9 个 token 不同、标题完全相同，标题位置 T 高几乎由构造决定：T(L4) 已是 0.983 / 0.976 / 0.998，T − T(L4) 在 L16–L40 为 −0.03 到 −0.06，I(l) − I(L4) 在所有层都 < 0，即中间层并不比 L4 更跨问法一致。X1 相似度检查显示 L24–L40 同篇两问法状态本来就相近（question share 0.15–0.17），所以"恢复一样好"部分来自构造；但 share 不为 0 而 a − year、a − field 差 ≤ 0.02，说明问法带来的差异不影响作者恢复。另外 random C 在 L4–L16 为负、L48 为 +0.122，记 NULL FLAG。见 s13-m3、s13-x1、h-prereg-dev。

Q14　X4 说 Qwen 能从论文自己的状态解码第一作者，文本基线排除了"标题风格"吗？

只部分排除。文本基线 1（kNN）的阳性对照失败（允许同团队时 TF-IDF −0.025、BERT −0.159），所以它的"文本解释不了"不成立。文本基线 2（监督 LR）只在名字首 token 上通过阳性对照、姓首 token 上失败；起草时还发现它对 821 篇没有 given_first 的论文仍计入了与姓名无关的 OOV 类概率差。总编 2026-10-30 用 CPU 只按实际存在的角色重算：BERT D_text +0.048 [+0.014, +0.083]，与 Qwen D(L8) 逐篇相关 +0.014。逐 token 全量（作业 11500437，b7 逐值复现已存分数）按角色拆开后：Qwen L8 信号主要在姓的首 token（+0.066 [0.045, 0.088]），名的首 token 只有 +0.018 [−0.003, 0.041]，而在名的首 token 上 BERT 文本基线 +0.088 反而更大；姓这个角色上文本基线的阳性对照没有通过。所以不能排除 L8 作者信号可由标题文字解释（措辞待用户最终确认）。见 s13-x4。

Q15　既然规定"容差不达标只记 WARN"，为什么 x4tok 失败就停了？
