  • 上下文与 teacher forcing（Stage 10 起；文档串称"each author alone after "Authors:", as Stage 6"）：input_ids = prompt_ids + name_ids[:-1]；名字第 j 个 token 在位置 len(prompt_ids) − 1 + j 被预测（j = 0 在 ":" 处预测）。最后一个名字 token 只作目标，不作输入。351_stage10.py:563 · protocol.json input_ids

G5.1 名次与 log10(1/名次)

对一个读出（readout r、层 l）在某位置给出的 logits z ∈ ℝ^V（V = 151,936，lm_head 全部输出行）和金标准 token g：
  rank  = 1 + #{ v : z_v > z_g }                 （严格大于；并列不往后排 = 对金标准有利）
  ties  = #{ v ≠ g : z_v = z_g }                  （另存，不进入 rank）
  nlr   = log10(1 / rank) = −log10(rank)          （rank 1 → 0；rank 10 → −1；最小 −log10(151,936) ≈ −5.18）
  logprob = log_softmax(z)_g                       （另存；不同读出之间不可比）
  • 代码：score() 351_stage10.py:442–449；protocol rank, ties, logprob 三项写明这一定义；Stage 11–13 用同一函数（s11.ranks 调 s10.score，361_stage11.py:192–193）或相同表达式（381_stage13.py:200–205 score_tf；stage13_gpu_followup.py _x4tok）。
  • 不去掉特殊 token，也不去掉 267 个填充行：比较对象是 lm_head 的全部 151,936 个输出。logits 是 bf16 的 lm_head 输出转成 float（model.unembed(h).float()），所以并列较常见：例 1 第一作者的 " Kar" 在 true 条件下 rank 83、并列 6 个（G4.3 数据）。Stage 10 parity 修订：快路径与逐前缀参考路径最大 |Δlogit| 0.16–0.37（约 1–1.5 个 bf16 单位），容差在看到数据后从 0.25 放宽到 0.5（用户 2026-10-25 批准）。351_stage10/config/analysis_plan.json amendments · reports/parity.json tolerance_amendment

  • 连写打分（Stage 11 E3、Stage 12 N1）：chain_ids() 把同一篇的全部作者按顺序接成 prompt + 名字1 + "," + 名字2 + …；每个名字 token 在它前一个位置被预测并打分；"," 只作输入、不打分；输出保留 Stage 10 的 row_id，所以连写分数与单独分数逐 token 配对。连写里第一位作者的上下文与单独打分完全相同，smoke 检查要求两者名次一致率 ≥ 0.75、平均 |Δlog10 rank| ≤ 0.05（不达标记 WARN，不停 GPU）。361_stage11.py:286–305, :439–444, :470
  • 一篇论文的分数（paper_scores()，351_stage10.py:651–667）： 
    mean_nlr(p, r, l)        = 该论文所有被打分作者的所有名字 token 的 nlr 的平均        ← 主指标（token 加权，punct 也在内）

G5.4 标题特异信号与组间比较

对每篇论文 p、读出 r、层 l、指标 m（主指标 m = mean_nlr）：
  true_m   = m(真标题)
  false_m  = (1/5) Σ_{k=0..4} m(false_k)        K_FALSE = 5 个按元数据匹配的假标题，年份保留本篇的
  delete_m = m(删标题)
  spec_m   = true_m − false_m                   ← 标题特异信号
  total_m  = true_m − delete_m
  topic_m  = false_m − delete_m
  spec_strict_m = true_m − mean{ m(false_k) : 供体属于 strict 层 }（没有 strict 供体则为 NaN）
  tail_fraction = (1 + #{k : mean_nlr(false_k) ≥ mean_nlr(true)}) / 6       （参考尾部比例，不是 p 值）

七个条件用的是同一组名字 token（同一篇、同样的作者和 token），只换 prompt，所以名字本身好不好猜在差值里抵消。351_stage10.py:838–870（analyze_title）· :243–248（K_FALSE, DELETE_PROMPT, TIERS, NEAR_DUP_JACCARD）· 结果 351_stage10/summary_title/paper_title_contrasts.parquet

假标题的匹配（match_false_titles，:255–307）：同领域；排除自身、与本篇共享任何姓氏的论文、标题词 Jaccard（≥4 字母的词，ASCII 化小写）> 0.6 的论文；代价 |Δyear|/5 + |Δn_authors|/max(1, 0.25·n) + |Δtitle_tokens|/max(1, 0.2·len) + 1.5·|Δbin|；按 strict → medium → loose → nearest 四层，每层反复做最小代价指派（scipy.optimize.linear_sum_assignment），每个供体最多用 5 次（nearest 层 7 次）；false_0 = 层级最好、代价最低的那个。具体层级容差见 config/conditions_manifest.json matching.tiers，属 Stage 10 章节。

target − control 比较（stratified_diff，:670–691）：只在两组都 ≥ 30 篇的引用档内做差（MIN_STRATUM = 30，主分析为 0-2 … 513-1024 共 10 档），按 w_b = n_t·n_c/(n_t+n_c) 归一化加权；95% CI = 在"档 × 组"内对论文有放回重抽 2,000 次（B_BOOT = 2000）的 2.5/97.5 分位；标题分析的随机种子 3511（:875）。
