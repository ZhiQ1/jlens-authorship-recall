# 待做：四个新方向的实验设计（2026-11-14，全部作者、全部名字 token 版）

共同约定（四项都适用）
- 打分单位：每篇论文的**全部作者、全部名字 token**；单个作者分数 = 该作者所有名字 token 的 mean log10(1/rank)（与补充 9 / 补充 10 相同的 score_tf）；论文分数 = 作者平均；另报"第一作者首 token"作对照。
- 区间：存档作者团队整群 bootstrap，2,000 次（381_stage13/summary_cpu_teamci/folds_own9108_k5s13.npz 的 team）；组间比较在同一组抽样上取差。
- 标题特异：凡是内部分数，都同时报 真标题 − 5 个假标题平均（spec），避免把"名字好猜"当成知识。
- 分组：A（认得出、一个作者都没写出，R0 × pass）、B（认不出、没写出）、U0（不确定、没写出）、C（认得出、写出部分作者，只看没写出的作者）、D；n < 30 只作描述。
- 每项开跑前：先写预注册（判据、样本、主比较），CPU 预检 → 小模型全流程 → 1 个分片 → 其余；GPU 作业 ≤ 45 分钟，killguard 排除。超过 5 GPU 小时的项先问用户。
- 结果写法：每项只讲 方法 / 数据 / 关键数字 / 结论。

运行顺序：0 → 2 → 1 → 3 → 4（先 CPU、后 GPU；0 的结果决定 1 的格式条件）。

## 2. 认得出和说得出，各需要多大的"曝光量"？（CPU，约 1 小时，先做）
**问题**：随引用数增加，是不是先出现"认得出"，很久以后才"说得出"？两者之间有没有固定的门槛差？内部信号是平滑增长还是在某一档跳升？
**数据**：9,108 篇（Stage 10 队列），13 个引用档；行为标签（选择题答对 0–4 次、开放回忆 R0/R1/R2）；内部分数全部作者、全部 token：输出层 spec、logit L62、public J-lens L48/L62、标题位置 probe L40（补充 9 全 token）、名字位置 probe L40/L48（补充 11）。
**分析**
1. 两条行为曲线：P(认得出) 和 P(说得出 ≥ 1 个作者) 对 log10(1 + 引用数) 做逻辑回归（年份作协变量，因为老论文引用多）；各自的 50% 门槛引用数及门槛差，团队 bootstrap CI。
2. 每个内部分数对 log 引用数：平滑（线性 / 样条）vs 分段回归（一个断点），比较 AIC；断点位置的 bootstrap CI；断点是否与行为门槛重合。
3. 条件分析：在"认得出"的论文里，内部信号能否预测"说得出"（AUROC，按引用档分层，团队 CI）——内部信号够强才说得出，还是与强度无关？
4. 全 token vs 第一作者首 token 两版并列。
**判据（预注册时固定）**：门槛差的 CI 不含 0 → "认得出先于说得出"；分段模型 AIC 低于平滑模型 ≥ 10 且断点 CI 宽度 ≤ 2 个引用档 → "存在跳升"。
**局限**：引用数只是训练数据曝光量的代理；标签来自另一次生成运行。
**输出**：391_groups/summary_exposure_20261114/（曲线、门槛、断点表、报告）。

## 1. 说不出，是不是卡在"必须先写的第一个 token"上？（GPU，估约 3–4 GPU 小时）
**问题**：模型可能知道姓，但名字要先写名或首字母，首字母几乎不带信息（第 55、59 页）。换输出格式后，说得出的比例会不会上升？
**数据**：A 组 600 篇 + B 组 600 篇（按 Stage 11 样本的引用档分布在档内抽，numpy default_rng 固定种子），C 组 300 篇作参照；每篇全部作者。
**条件（同一篇论文的不同提示，其余与 Stage 10 相同）**
- F0 原格式："Authors:"（复现基线，用来校准我们这套提示与标注运行的差别）
- F1 姓在前："Authors (surname, given name):"
- F2 只写姓："Author surnames:"
- F3 只问第一作者姓："First author's surname:"
- 每个条件都有 真标题 / 5 个假标题平均 两版（只用于教师强制部分）。
**两种测量**
1. 生成（贪心解码，最多 80 个新 token，关闭 thinking）：用现有匹配器（姓 + 首字母，两种顺序）判定写对的作者；论文级"至少写对 1 个"、作者级召回率、编造名字比例。
2. 教师强制：把真作者按该格式写出来，打全部名字 token 的分数（score_tf），以及格式下第一个 token 的名次；spec = 真标题 − 5 个假标题平均。
**主比较**：A 组内 召回(F1) − 召回(F0)、召回(F2) − 召回(F0)，团队整群 CI；同样的差在 B 组里算一遍，A − B 的差中差判断是不是"认得出的论文特有的"格式锁定。
**判据**：A 组 F1 或 F2 相对 F0 的召回差 CI 不含 0 且 > 0，并且差中差 > 0 → "隐藏知识部分被输出格式锁住"；都不显著 → 排除这一解释（也写进结论）。
**对照与检查**：编造率同时报（防止只是多写名字）；F0 与标注运行的召回率对比（若差很多，结论只限于我们的提示）；只用姓匹配的宽松版并列。
**算力**：1,500 篇 × 4 条件生成 + 教师强制打分，Qwen3-32B bf16，单卡 A100-80GB；估约 3–4 GPU 小时（开跑前用 1 个分片实测再定，超过 5 小时先问）。
**输出**：391_groups/raw/fmt_*/、summary_format_20261114/。

## 3. 合作者链：写对一个名字，能不能带出下一个？（GPU，估约 2 GPU 小时）
**问题**：已知前面的作者能帮助后面的作者（第 58 页 +0.17 到 +0.23），而写对部分作者只帮合作者、不帮第一作者（第 29 页）。真名字作提示时，帮助是"这篇论文的记忆被唤起"，还是"任何名字都行"？方向是否对称？
**数据**：A、C 组各 600 篇（档内抽样），只用作者数 ≥ 3 的论文；全部作者、全部 token。
**条件（教师强制，在 "Authors:" 后先给 k 个名字，再给剩下的作者打分）**
- P_true(k)：前 k 个真作者（k = 0, 1, 2）
- P_other(k)：同领域另一篇论文的前 k 个作者（名字是真的，但不是这篇的）
- P_shuffle：这篇论文的作者打乱顺序后取 k 个（检验顺序是否重要）
- P_reverse：先给后面的作者，再给第一作者打分（检验"合作者 → 第一作者"方向）
- 每个条件 真标题 / 5 个假标题平均 / 删去标题 三版。
**测量**：剩余作者的全 token 分数；链增益 = P_true(k) − P_other(k)（只算"这篇论文的名字"带来的部分）；标题特异部分 = 真标题 − 假标题；看链增益在没有标题时是否更大（合作者能否替代标题）。
**判据**：链增益 CI 不含 0 且 > 0 → "一个真名字能带出同一篇论文的其他作者"；P_reverse 的增益显著小于正向 → 方向不对称（与第 29 页一致）。
**附加（可选，生成）**：给第一个真作者，生成其余作者，看召回是否上升（A 组 300 篇）。
**算力**：1,200 篇 × 约 10 个条件的前向打分，估约 2 GPU 小时。
**输出**：391_groups/summary_chain_20261114/。

## 4. 把"自己写的名字真假可分"（C24）做成有对照的检测工具（GPU，估约 3–5 GPU 小时）
**问题**：probe 在名字 token 上区分真作者与编造名字（论文内 AUROC 0.78），在控制输出置信度之后还有没有增量？能不能用来改进写对的比例？
**步骤**
1. 置信度基线收尾：先做已批准的只读核查（第 0 片重放 argmax 与生成不一致的约 2.1% 位置：对数概率差是否在几个 bf16 单位内、是否集中在名字 token、对名字置信度分数影响多大），按结果决定：记 WARN 用重放概率 / 放宽门槛 / 重新生成并保存 logits。
2. 增量检验：每个名字的输出置信度（全部名字 token 的平均 log-prob、熵、最小 log-prob）作基线；probe、置信度、两者合并三个模型同样的 5 折团队交叉验证；论文内 AUROC 的配对差（probe − 置信度、合并 − 置信度），团队 bootstrap CI。
3. 应用：A、C 组 500 篇，每篇采样生成 10 份作者名单（温度 0.7），所有候选名字取并集；按 probe 分数、按置信度、按两者合并分别排序或过滤，比较"前 k 个名字里写对的比例"和"写对至少 1 个作者的论文比例"（菜单式候选：与 Yi Feng 的菜单方法对接，作为一个条件）。
**判据**：合并 − 置信度 的 AUROC 差 CI 不含 0 → "probe 在输出置信度之外有增量"；应用部分 probe 排序的写对比例显著高于置信度排序 → "可用于改进回忆"。
**全 token**：probe 用名字全部 token 残差的平均（与 C24 主分析一致），置信度也用全部 token。
**算力**：重放核查 CPU；若要重新生成并保存 logits + 10 份采样 + 残差记录，估约 3–5 GPU 小时（开跑前实测，超过 5 小时先问）。
**输出**：381_stage13/summary_c24_tool_20261114/。
